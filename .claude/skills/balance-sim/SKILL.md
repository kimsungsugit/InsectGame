# 밸런스 시뮬레이션

지정된 시스템의 수치 밸런스를 시뮬레이션하고 분석합니다.

## 시뮬레이션 유형

### battle (1v1 배틀)
- 레벨별 데미지 기대값 계산
- ATK/DEF 비율에 따른 데미지 곡선
- 버프/디버프 스택 시 최대/최소 데미지
- 특정 매치업 시뮬레이션 (레벨/스탯 입력)

### capture (포획)
- 레어도×레벨 조합별 포획률 테이블
- 아이템 보너스 적용 시 변화
- 미니게임 성공률 (속도/존크기 기반)

### raid (레이드)
- 보스 HP vs 팀 DPS 계산
- 유나이트 게이지 충전 속도
- 생존 턴 수 추정

### levelup (이관됨)
레벨업/진행 시뮬은 `/progression-sim`이 더 정밀하게 다룹니다 (누적 곡선 + 데드존 + 레어도 격차 + 플레이시간 + 팀 비용 등 7개 위험 신호 자동 검출).

**`/balance-sim levelup` 호출 시 동작**: 본 스킬은 레벨업 시뮬을 직접 실행하지 않고 `/progression-sim`으로 자동 위임합니다. 사용자에게 "레벨업/진행 시뮬은 /progression-sim 호출이 필요합니다. 인자 없이 실행하면 기본값(Lv50, Common)으로 동작합니다." 안내 후 종료.

## 절차 — 이 스킬엔 backing 스크립트가 없다

형제 sim 3개(`/progression-sim`, `/economy-sim`, `/gacha-sim`)는 커밋된 `.py`가 돌지만
**`balance_sim.py`는 없다.** 이 스킬은 모델이 코드를 읽고 손계산한다.
(한때 이 자리에 "2. Python 스크립트로 시뮬레이션을 실행합니다"라고 적혀 있었다 —
존재하지 않는 스크립트를 부르라는 거짓 약속이었다.)

1. 코드에서 공식·상수를 **직접 읽는다** — `GameConstants`, `InsectBattleController`,
   `CaptureController`, `RaidBattleController`. 이 문서나 `rules/balance.md`의 숫자를
   믿지 말 것. 수치의 단일 출처는 코드다.
2. 읽은 공식으로 표를 계산한다. 계산이 길면 그 자리에서 일회용 파이썬을 짜서 돌리되,
   **`.claude/scripts/`에 커밋하지 않는다** — 상수를 베낀 스크립트는 또 하나의 사본이 된다.
   장기 시뮬이 필요하면 아래 형제 스킬을 쓸 것.
3. 결과를 테이블로 출력한다. **어떤 파일의 어떤 값을 읽었는지 함께 밝힌다.**
4. 밸런스 이슈가 있으면 조정안을 제시한다.

## 장기 시뮬은 별도 스킬 사용

이 스킬은 **단일 시점의 수치**(전투 1회/포획 1회 등)에 집중합니다. 장기 진행/누적 분포가 필요하면:
- `/progression-sim` — Lv1→50 캔디·EXP 누적 곡선, 데드존 검출
- `/economy-sim` — 통화 수입·지출 균형, 데드 화폐/병목/P2W 검출
- `/gacha-sim` — 박스 몬테카를로(10000회) + UI-코드 정합성 자동 점검
