# Explore 표준 가드

Explore 서브에이전트에게 잠재 문제 탐색을 위임할 때, 다음 가드를 프롬프트에 명시한다. 직전 라운드들에서 거짓양성률이 평균 50%였던 원인을 차단하기 위함.

## 위임 프롬프트에 반드시 포함할 가드

### 1. 거짓양성 금지 조건 (보고 전 자기검증)
다음에 해당하면 **보고 금지**:
- **Unity 메인스레드 단일 실행 모델 race**: `lock`/`Thread-safe collection`/`Interlocked` 권장 → Unity는 메인 스레드 단일이라 같은 프레임 다중 호출도 순차. 보고 금지.
- **이미 가드 있는 코드**: `if (x != null)` / `if (x > 0)` 같은 가드가 이미 있는데 "null 가드 누락"으로 보고 금지. **반드시 해당 라인을 read하여 가드 존재 확인 후 보고**.
- **idempotent 표준 패턴**: `-=` 후 `+=` (이벤트 재구독 idempotent), `OnDisable` 해제 (표준 라이프사이클) 보고 금지.
- **메인 호출처 0개인 silent fail**: 외부 호출처가 0개이면 영향 없음. grep으로 호출처 확인 후 P2 미만으로 격하 또는 미보고.

### 2. 사용자 프롬프트에 명시되는 "이미 처리 영역" 자동 제외
위임자가 "**이미 처리됨 (제외)**" 섹션을 명시하면 그 영역은 절대 보고하지 말 것. 항목 하나라도 해당 영역에 속하면 스킵.

### 3. 실제 코드 검증 필수
- 보고하기 전 해당 파일/라인을 Read로 직접 읽고 가드 존재 확인
- grep 결과만으로 보고 금지 (가드 메서드는 grep에 안 잡힐 수 있음)

### 4. UI/이벤트 비대칭 보고 시 양쪽 모두 확인
- `OnEnable += X; OnDisable -= X` 짝이 맞는지
- `AutoWire`에서만 구독한다면 `OnEnable`도 같은 패턴인지 확인 후 보고

## 보고 형식 (강제)

각 보고 항목은 정확히 다음 5줄:

```
N. [심각도] 문제 한 줄 요약
파일: <상대경로>:<라인번호>
원인: <왜 문제인지 1~2줄>
권장: <수정 방향 1줄>
이미 처리됐을 가능성: 낮음|중간|높음 (이유 1줄)
```

### 심각도 기준
- **P0**: 데이터 손실/크래시/사용자 진행 차단. 즉시 수정 필요.
- **P1**: 메모리 누수/UI 비일관/주요 흐름 결함. 우선 수정.
- **P2**: silent fail/잠재 최적화. 후순위.
- **P3**: 가독성/스타일. 보고 생략 가능.

P3은 별도 요청 없으면 생략. P2도 5건 이상이면 P1 우선.

## 보고 길이 제약

총 300단어 이내. 항목 5건 이상 발견 시 P0/P1만 우선 보고. P2는 묶어서 1줄 요약.

## 위임자 책임

위임 프롬프트에 반드시 포함:
- "**이미 처리됨 (제외)**" 섹션 (직전 라운드 수정 목록)
- "**점검 영역**" 섹션 (이번 라운드 의심 후보)
- "위 explore-standard.md 가드 준수" 명시 (이 파일 인용 또는 핵심 가드 인라인)
