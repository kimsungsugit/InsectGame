# 나의 섬 (개인 섬 하우징) 기획서

상태: **구현됨** (2026-10-02 승인·구현). 이 문서는 **왜 이렇게 지었는가**를 남긴다.
수치의 단일 출처는 코드(`GameConstants.Island`·`IslandCatalog`·`IslandYield`)이고 유지 규칙은 `.claude/rules/island.md`다 —
여기에 숫자 사본을 두지 않는다(대역만 적는다).

## 1. 개요

캐릭터마다 섬 하나를 준다. 보유 곤충 몇 마리를 풀어놓으면 섬을 돌아다니며 시간에 따라 캔디·코인을
만들고, 플레이어는 그걸 수확해 건물·가구·지형지물·도구를 사서 칸 단위로 배치한다. 섬은 친구에게
공개할 수 있고 친구는 저장된 모습을 걸어다니며 구경한다.

결정된 방향(2026-10-02 사용자 선택):

| 항목 | 결정 |
|---|---|
| 곤충 역할 | 방목 + 시간 보상(접속 안 한 시간도 상한까지 누적) |
| 배치 | 칸 단위 자유배치(회전·이동·회수) |
| 공유 | 스냅샷 방문(읽기 전용, 비동기) |
| 화폐 | 기본은 코인, 프리미엄은 다이아(젬). 섬·곤충 자리 확장은 코인으로도 다이아로도 |
| 진행 | 계획 승인 후 끝까지 |
| 서버 배포 | 함수 코드와 테스트만 작성 — 배포는 사용자가 직접 |
| 해금 | 「곤충 수집가」(`q_capture3`) 완료 후 |

목적: ①전투·포획 밖의 **매일 들를 이유** ②코인의 쓸 곳(현재 코인 소비처는 의상·병원뿐) ③다이아 소비처
④친구 기능에 전투 말고 보여줄 것.

## 2. 상세 설계

### 2.1 들어가고 나오기

- **퀵바 메뉴 「내 섬」** + **본 마을 나루터**(상호작용 지점) 두 경로.
- 섬은 메인 월드와 분리된 좌표 `(3000, 0, 3000)`에 짓는다(서브에리어 2000·배틀 아레나 1000과 안 겹침).
- 나갈 때는 들어오기 전 자리로 돌아간다. 섬 안 HUD의 「나가기」 또는 나루터.
- 섬에서는 야생 스폰·포획·전투가 없다.

### 2.2 섬 안에서 할 수 있는 것 (하단 HUD)

| 버튼 | 내용 |
|---|---|
| 꾸미기 | 편집 모드 진입 — 보관함에서 골라 칸에 놓기, 놓인 것 탭해서 이동·회전·회수 |
| 상점 | 건물 / 가구 / 지형지물 / 도구 / 확장 5탭 |
| 곤충 | 방목할 곤충 고르기·교체, 친밀도 보기 |
| 수확 | 쌓인 캔디·코인 받기 (쌓인 양과 가득 찰 때까지 남은 시간 표시) |
| 방문 | 친구 섬·섬 코드로 방문, 내 섬 공개 설정, 좋아요 수 |
| 도움말 | 가이드 다시 보기 |
| 나가기 | 메인 월드로 |

### 2.3 배치 규칙

- 섬은 격자(1칸 = 1.5m). 물건마다 차지 칸(가로×세로)이 있고 90° 단위로 회전한다.
- 겹침 금지, 섬 경계 밖 금지, 나루터 앞 도착 칸은 비워 둔다(막으면 들어오자마자 갇힌다).
- 회수하면 보관함으로 돌아간다. **되팔기는 없다** — 다이아 환급은 서버 규칙상 불가능하다(4.4).
- 편집 모드에서는 캐릭터 이동을 멈춘다. 지면 탭이 「배치」와 「클릭-이동」 둘 다로 읽히는 걸 막기 위해서다.

### 2.4 방목과 수확

- 보유 곤충에 「섬 방목」 표시를 붙인다(배틀팀과 같은 구조 — 곤충은 그대로 보유 목록에 있고 전투에도 쓸 수 있다).
- 방목 중인 곤충은 섬 위를 천천히 돌아다닌다. 탭하면 이름·친밀도가 뜬다.
- 시간이 지나면 캔디·코인이 쌓인다. 상한(기본 8시간분)에 닿으면 멈춘다 → 수확하러 들를 이유.
- **친밀도**: 방목 시간에 따라 오른다(하트 0~5). 효과는 **섬 생산량 보너스뿐** — 전투 스탯에 손대지 않는다.
- **쾌적도**: 놓인 물건의 쾌적도 합. 생산량 보너스. 같은 물건을 도배해도 오르지 않게 종류 수로 체감시킨다.
- **도구**(먹이통·급수대·수확 바구니 등)는 놓아두면 효과가 나는 설비다: 생산 +%, 상한 시간 +, 친밀도 속도 +.

### 2.5 공유(스냅샷 방문)

- 편집 모드를 닫을 때 섬의 현재 모습을 서버에 올린다(공개 설정이 켜져 있을 때만).
- 방문: 친구 목록에서 고르거나 **섬 코드**(기존 친구 코드 8자리 재사용)를 입력한다.
- 방문 중에는 걸어다니며 구경만 한다. 편집·수확 불가. 「좋아요」 하루 1회.
- 상대가 접속 중이 아니어도 된다. 실시간 동석은 이번 범위 밖(구조만 열어둔다).

### 2.6 퀘스트 (서브 퀘스트, 전부 Side)

| ID | 제목 | 목표 | 보상의 성격 |
|---|---|---|---|
| `s_island_arrive` | 나의 섬 | 섬에 들어가기 | 코인(첫 구매 밑천) + 등불 |
| `s_island_place` | 꾸미기 시작 | 물건 3개 배치 | 코인 + 꽃밭 |
| `s_island_release` | 첫 손님 | 곤충 2마리 방목 | 캔디 + 먹이통 |
| `s_island_harvest` | 첫 수확 | 수확 1회 | 캔디 + EXP |
| `s_island_shop` | 섬 상점 | 상점에서 1개 구매 | 코인 |
| `s_island_visit` | 이웃 섬 구경 | 다른 사람 섬 방문 1회 | 캔디 + 팻말 |
| `s_island_keeper` | 섬지기 (반복) | 수확 N회, 달성마다 목표 상승 | 캔디·코인 소량 |

값은 `TutorialQuestManager`의 배열이 단일 출처다. 보상에 다이아는 넣지 않는다(4.4).
앞 다섯 개가 곧 **가이드의 본체**다 — 하나씩 따라 하면 기본 조작을 전부 한 번씩 해 보게 된다.
섬 첫 진입 때는 퀘스트와 별개로 **스타터 키트**(벤치·화분·어린 나무)가 보관함에 들어온다 — 안내가 "보관함의 벤치를 놓아 보세요"로 바로 쓴다.

### 2.7 가이드

- 섬 **첫 진입 때 단계형 안내**(코치 배너): 섬 소개 → 꾸미기 버튼 → 보관함에서 벤치 놓기 → 곤충 방목 → 수확·상점·나가기.
  단계는 실제 행동으로 넘어간다(「다음」 버튼이 아니라 벤치를 놓으면 다음 단계).
- 수확 단계에 들어설 때 **첫 선물**(캔디·코인 약간)을 넣어 둔다 — 곤충 한 마리로는 캔디 1개에 네 시간이 걸려
  "수확을 눌러 보세요"가 성립하지 않는다.
- 이미 한 행동의 단계는 건너뛴다(다른 기기에서 꾸민 섬을 클라우드로 받아 온 세이브가 첫 단계에 멈추지 않게).
- 언제든 「도움말」로 다시 본다(항목별 설명 + "처음 안내 다시 보기"). 진행 위치는 섬 세이브에 저장.
- 배너는 **✕로 닫거나 12초가 지나면 사라진다**(남은 시간은 배너 아래 얇은 줄). 닫는 것은 화면에서 치우는 것뿐이라
  단계는 그대로고, 다음 단계에 가거나 섬에 다시 들어오면 그 단계 안내가 다시 뜬다. 마지막 인사는 닫는 것이 곧 확인이다.
- 모바일 필드에서는 **화면 가운데 줄, 캐릭터 발 아래**에 놓는다 — 위쪽은 왼편에 미니맵·퀘스트 칩, 오른편에 퀵바·섬 버튼 줄이
  있어 빈 자리가 없다(처음엔 좌상단에 놓았다가 미니맵·퀘스트 칩 밑에 깔렸다). 꾸미기 화면 위에서는 상단 바 아래.
- 기존 `GuidedTutorialController`는 Story 퀘스트 활성 이벤트에 묶여 있어 Side 퀘스트로는 안 뜬다 → 섬 전용 가이드를 따로 둔다.

## 3. 수치 설계 — 대역과 근거

기준: `economy_sim`의 평소 활동 수입은 하루 캔디 약 156(포획 20·전투 10·레이드 주 3회), 코인은 전투 승리당 3이라 하루 약 30.
다이아는 유료 전용이다(무료 지급 경로 0건).

| 지키려는 것 | 대역 | 어디서 검사하나 |
|---|---|---|
| 기본 섬(일반 3마리)의 캔디 | 활동 수입의 20% 이하 (현재 12%) | `economy_sim` 신호 6 · `IslandYieldTests` |
| 풀 확장 섬(전설 최대 마리·보너스 전부)의 캔디 | 활동 수입의 125% 이하 (현재 113%) | `economy_sim` 신호 7 · `IslandYieldTests` |
| 도배로 생산이 오르지 않을 것 | 쾌적도는 종류로 체감, 설비 효과는 id당 한 번 | `IslandYieldTests` |
| 방치하면 멈출 것 | 누적 상한(기본 8시간, 설비로 최대 16) | `IslandYieldTests` |

- **섬 전용 등급 배율을 따로 둔 이유**: 보상 배율(전설 2.8)을 그대로 쓰면 전설 10마리 섬이 하루 300캔디를 넘겨 활동 수입의 두 배가 된다.
  섬은 곁들이는 수입이라 폭을 눌렀다(전설 1.6).
- **섬이 코인을 만드는 이유**: 코인 수입이 전투 승리 3코인뿐이라, 섬이 코인을 만들지 않으면 가구를 사는 순환이 돌지 않는다.
  코인 생산은 등급을 보지 않는다 — 코인은 꾸미기 재화라 수집 깊이와 묶지 않는다.
- **확장을 코인으로도 살 수 있게 한 이유**: 다이아가 유료 전용이라, 섬 크기·곤충 자리를 다이아로만 팔면 무과금은 기본 섬에 갇힌다.
- **친밀도가 전투 스탯에 손대지 않는 이유**: 섬에 오래 둔 곤충이 전투에서 세지면 섬이 필수 콘텐츠가 된다. 효과는 섬 생산량뿐이다.
- 카탈로그 28종: 건물 5 · 가구 10 · 지형지물 8 · 도구 5.

## 4. 시스템 연결

### 4.1 섬은 「합성 서브에리어」로 탄다

"분리된 공간에 있다"는 판정이 전부 `RegionManager.CurrentSubArea != null`에 걸려 있다
(PlayerMovement 접지·끼임 복구, InsectSpawner 필드 틱, MinimapUI, RegionMapUI, SubAreaEnvironment, BlightVfx).
섬을 별개 상태로 만들면 그 전부를 따로 고쳐야 하고, 빠뜨리면 왕복할 때마다 `RegionChanged`가 재발화해
방문 퀘스트·스토리 트리거·BGM이 오작동한다.

그래서 `RegionManager.EnterDetachedSubArea`(위치와 무관한 진입)를 두고 섬을 `SubAreaData.detached = true`인
합성 구역(id `player_island`)으로 태운다.

- `SubAreaWorldBuilder`는 `detached` 구역을 건너뛴다(방 생성·25m 자동 이탈·퇴장 버튼). 섬은 `IslandWorldBuilder`가 짓는다.
- 전용종이 비어 있으므로 `InsectSpawner`는 몸을 거두고 아무것도 스폰하지 않는다(기존 동작 그대로).
- `VisitSubArea` 퀘스트는 `detached` 구역을 세지 않는다. 스토리 `SubAreaEnter`는 섬 id에 걸린 비트가 없어 지나간다.
- `SubAreaEnvironment`에 섬 조명 프로필, `PlayerMovement` 끼임 복구는 섬 도착 칸으로 분기.
- 방목 곤충은 `InsectEntity.BuildForBattle` 경로로 세운다 — 야생 스폰 경로로 세우면 섬 위에서 플레이어를 보고 달아나고 잡기 버튼이 뜬다.

### 4.2 세이브

- 로컬: `island.json` 신규(계정 스코프). 보관함·배치·방목 목록·친밀도·마지막 정산 시각·확장 단계·가이드 진행·공개 설정.
- 클라우드: `GameSaveData.islandData` 블롭 1개(수집·직렬화·파싱·복원 + `SaveScope.ScopedFiles` + `RegisterReloadable`).
- 구세이브 호환: 파일이 없으면 기본 섬(0단계, 스타터 키트 미지급 상태). 필드 기본값만으로 성립하게 선언.
- 방목 목록은 `instanceId`로 든다. 로드·클라우드 복원 때 보유 목록과 대조해 없는 id는 버린다.
- 오프라인 누적은 기기 시계(UTC)로 잰다. 시계를 되돌려 음수가 나오면 0으로 본다. 상한이 있어 시계 조작의 이득은 한 번의 상한분이다.

### 4.3 화폐

- 코인 `wallet.SpendCoins`, 다이아 `wallet.SpendGems`(잔액 검사·차감·즉시 클라우드 저장이 한 번에 됨).
- 구매 순서: 차감 → 보관함 기록·저장 → 클라우드 저장 한 번 더(차감 직후 스냅샷엔 소유권이 아직 없다).

### 4.4 서버 제약 (코드로 확인)

- `firestore.rules`: 클라이언트는 다이아를 **줄이기만** 할 수 있다. 늘리면 `users/{uid}` 업로드 전체가 거부된다
  → 되팔기 환급·퀘스트 다이아 보상 불가.
- 타인 문서는 클라이언트에서 직접 못 읽는다. 친구 기능은 전부 Cloud Function `socialPvpApi` 경유
  → 섬 공유도 거기에 액션 5개(`publishIsland` / `getMyIsland` / `getIsland` / `likeIsland` / `deleteIsland`)를 얹고
  `islands/{uid}`에 저장한다. 규격·오류 코드·배포 명령은 `Docs/SocialPvp.md` 「섬 공유」. **함수 배포가 필요하다**(사용자가 직접).
- 서버가 배포되기 전에도 내 섬 기능은 전부 동작하고, 방문만 "준비 중"으로 뜬다.
- **2026-10-02 현재 미배포이고, 배포하지 않기로 정했다.** 운영 프로젝트에는 `socialPvpApi` 자체가 올라간 적이 없어서
  (함수 0건, 주소 404) 섬 공유 배포 = 친구·PvP·월드 채널까지 포함한 온라인 기능 전체의 첫 운영 배포가 된다.
  그 동안 서브 퀘스트 `s_island_visit`(이웃 섬 구경)은 완료할 수 없다.

### 4.5 Bootstrap 등록

`World/IslandManager`(로직·세이브) → `World/IslandWorld`(지형·실체화) → `UI/Island*`(HUD·편집·상점·곤충·방문·가이드).
`IslandManager`는 `insectCollection`·`wallet`·`candyInventory` 뒤, `cloudSave.RegisterReloadable`은 곤충 컬렉션 뒤.
새 싱글턴은 만들지 않는다(AutoWire).

## 5. UI/UX

- 섬 HUD·편집 트레이는 **필드 위 비모달**이라 매 프레임 `FieldHudInput.RegisterBlockingRect` 등록.
- 상점·곤충·방문 창은 `IModalUI` 전체 패널(`UISafeLayout.CenteredPanel` + `UISurface`).
- 색은 `UITheme` 토큰, 데이터 길이 문구는 `UIHelper.LabelFit`.
- 편집 모드: 칸 하이라이트(놓을 수 있음 민트 / 못 놓음 코랄), 하단 트레이(보관함 가로 스크롤), 선택 물건 위 「회전·확정·회수」.

## 6. 데이터 구조

- `IslandObjectDef` — id, 이름, 설명, 분류(건물/가구/지형/도구), 차지 칸, 코인가·다이아가, 쾌적도, 효과, 해금 조건.
- `IslandCatalog` — 코드 정의 정적 카탈로그(의상 카탈로그와 같은 방식).
- `IslandSave` — `[Serializable]` 일반 클래스, `JsonUtility`.
- `IslandSnapshot` — 공개용 축약본(배치 + 방목 곤충의 종·레벨·샤이니 + 주인 이름·좋아요 수). 개인 정보·instanceId는 싣지 않는다.

## 8. 테스트 항목

- 격자: 겹침 거부, 경계 밖 거부, 회전 시 차지 칸, 도착 칸 보호, 섬 축소가 없으므로 확장 뒤 기존 배치 유효.
- 생산: 등급 배율, 상한 clamp, 음수 경과 = 0, 쾌적도·친밀도 상한, **풀 확장 섬 일일 캔디가 대역 안**(수치 변경 감지).
- 카탈로그: id 유일, 가격 둘 중 하나는 양수, 차지 칸 ≥ 1, 퀘스트 보상 id 실재.
- 세이브: 빈 JSON → 기본 섬, 없는 instanceId 정리, 모르는 물건 id 무시(구버전·신버전 혼용).
- 수동: 섬 왕복 뒤 방문 퀘스트·스토리 트리거·BGM이 재발화하지 않는지, 오프닝 다시보기 뒤 섬 UI 구독 유지.

## 9. 알려진 한계 (이번 범위)

- IMGUI는 배치 캡처에 안 잡힌다 → 섬 UI는 QA 빌드 시나리오(`island-ui`)로만 눈 확인이 된다.
- 실시간 동석 없음. 방문자에게 주인 캐릭터는 보이지 않는다(곤충과 섬만).
- 계정 삭제 시 공개 섬 문서 삭제는 서버 액션으로 함께 넣는다(현재 `socialProfiles`도 안 지워지는 기존 문제와 같은 계열).
